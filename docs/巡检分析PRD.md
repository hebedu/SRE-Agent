# AI SRE 巡检助手 · 三种巡检结果分支原型说明

> 巡检分析流程采用**三阶段**结构：开始分析 / 巡检对象分析 / 最终结论。

---

## 一、整体页面结构

页面采用左右双栏布局。

```text
左侧：巡检任务列表 / 巡检对象列表
右侧：AI 分析对话窗口
```

右侧 AI 分析对话窗口按阶段输出分析内容，每个阶段作为独立时间线节点展示。

### 统一三阶段框架（所有分支一致）

```text
阶段 01：开始分析          （巡检计划信息 / 对象统计 / 巡检任务脚本）
阶段 02：巡检对象分析      （全部对象列表 / 对象分析）
阶段 03：最终结论          （当前判断 / 总体建议）
```

> 三个阶段标题在所有分支中**完全一致**，仅内部内容随分支（normal / abnormal / failed）动态变化。

### 三分支展示重点

| 巡检结果 | 展示重点 |
| --- | --- |
| normal | 覆盖完整性、对象列表、整体健康摘要、健康结论 |
| abnormal | 全部对象列表、异常/失败对象详情、异常指标、异常原因、处置建议 |
| failed | 全部对象列表、失败对象详情、失败原因、恢复建议 |

---

## 二、阶段 01：开始分析

所有分支包含三个子模块，结构一致，仅数据不同。

### 1. 巡检计划信息

| 字段 | 内容 |
| --- | --- |
| 巡检计划名称 | {计划名称} |
| 执行结果 | normal / abnormal / failed（对应彩色标签） |
| 执行时间 | {真实时间} |
| 严重级别 | info（普通）/ warning（警告）/ critical（严重） |

- normal：执行结果绿色、严重级别弱化
- abnormal：执行结果橙/红、严重级别 critical
- failed：执行结果红色、严重级别 critical

### 2. 巡检对象统计

| 统计项 | 数量 |
| --- | --: |
| 巡检对象总数 | 23 |
| 正常对象数 | 20 |
| 异常对象数 | 2 |
| 失败对象数 | 1 |

（各分支数量不同：normal 全部正常；abnormal 含异常+失败；failed 含失败）

### 3. 巡检任务脚本

列出本次巡检执行的任务脚本，所有分支结构一致。每个任务卡片包含：

```text
[序号] 任务名称
  执行范围：{N}个对象  [资源类型标签]
  执行内容：{脚本采集描述}
```

示例：

```text
1  连通性与环境检查
   执行范围：23个对象  [HOST]
   执行内容：采集 CPU、内存、磁盘（含 Inode）、系统负载、网络连接、进程数等7项指标，
            按阈值分级告警并输出 JSON 结构化报告。

2  JVM 堆内存分析
   执行范围：3个对象  [JVM]
   执行内容：采集 JVM 堆内存使用率、GC 频率、老年代占用百分比、元空间使用情况，
            判断是否存在内存泄漏风险。
```

任务字段：

| 字段 | 说明 |
| --- | --- |
| id | 任务序号 |
| name | 任务名称 |
| scopeCount | 执行范围（对象数量） |
| resourceType | 资源类型：HOST / JVM / MYSQL / REDIS（不同类型不同色标签） |
| scriptContent | 执行内容（脚本采集描述） |

> **展示规则**：`执行范围：` 和 `执行内容：` 为文本标签（非数字序号），中性灰样式。任务为空时整个模块省略。

## 三、阶段 02：巡检对象分析

包含两个子模块，所有分支结构一致。

### 1. 全部巡检对象列表

展示所有巡检对象（normal / abnormal / failed 全覆盖）。

**列表展示规则：**

```text
默认展示前 5 个对象
底部展示「查看全部对象 (总数)」按钮
点击后打开弹窗展示完整对象列表
```

| 序号 | 巡检对象 | 执行结果 | 严重级别 | 关键指标 |
| --- | --- | --- | --- | --- |
| 1 | 172.30.34.73:8001 | 异常 | 严重 | RSS=1821MB CPU=92% |
| 2 | 172.30.34.81:8001 | 异常 | 严重 | FD=980 接近上限 |
| 3 | 172.30.34.90:8001 | 失败 | 严重 | 连接超时 |
| 4 | 172.30.34.91:8001 | 正常 | 普通 | RSS=512MB CPU=32% |
| 5 | 172.30.34.92:8001 | 正常 | 普通 | RSS=498MB CPU=31% |

**弹窗规则：**

- 标题：全部巡检对象
- 展示所有对象
- 支持按 IP 搜索
- 支持按执行结果筛选（正常/异常/失败）
- 支持按严重级别筛选（普通/警告/严重）

### 2. 巡检对象分析

由**文本摘要**开头，之后**仅当存在异常/失败对象时**展示逐对象详情。

#### 2.1 文本摘要（所有分支）

自然语言总结本次巡检对象情况，例如：

> 本次巡检共覆盖 23 个对象，发现 2 个异常对象（CPU/内存超阈值）、1 个失败对象（连接超时），20 个对象运行正常。异常对象需重点关注资源使用情况，失败对象需排查网络连通性。

#### 2.2 异常或失败对象详情（仅 abnormal / failed）

**（1）异常或失败对象列表** —— IP 按钮选择器

```text
[● 172.30.34.73:8001 (异常)]  [● 172.30.34.81:8001 (异常)]  [● 172.30.34.90:8001 (失败)]
```

- 异常对象用琥珀色圆点，失败对象用红色圆点
- 点击 IP 按钮切换下方「对象详情」
- 默认选中第一个

**（2）对象详情** —— 根据对象类型分流展示

| 区块 | 出现条件 | 内容 |
| --- | --- | --- |
| 基础信息表 | 总是 | IP地址、类型、严重级别 |
| ├ 失败原因行 | **仅 type=failed** | 失败原因（如"连接超时"） |
| 影响说明 | 存在 impact 时 | 一句话影响描述 |
| 异常指标表 | **仅 type=abnormal** | 指标名称/当前值/阈值/状态 |
| 异常原因分析 | **仅 type=abnormal** | 根因分析段落 |

> **关键差异（对象类型分流）：**
> - **异常对象 (abnormal)**：基础信息**无**"失败原因"行；**有**异常指标表 + 异常原因分析。
> - **失败对象 (failed)**：基础信息**有**"失败原因"行；**无**异常指标表和异常原因分析（失败对象无法采集指标）。

异常指标表示例（abnormal）：

| 指标名称 | 当前值 | 阈值 | 状态 |
| --- | --- | --- | --- |
| CPU 使用率 | 92% | 80% | 异常 |
| RSS 内存 | 1821MB | 1500MB | 异常 |

> normal 分支无异常/失败对象，因此阶段 02 只展示"文本摘要 + 对象列表"，不展示对象详情。

## 四、阶段 03：最终结论

所有分支统一为两个子模块：**1. 当前判断** + **2. 总体建议**。内容与形态随分支不同。

### 4.1 normal 分支

**1. 当前判断**（无序列表）
- 当前系统运行状态稳定
- 暂未发现资源压力或错误率异常
- 无需立即处理

**2. 总体建议**（无序列表）
- 建议保持当前巡检策略
- 建议继续按计划执行后续巡检
- 如业务高峰期临近，可持续关注核心服务指标

### 4.2 abnormal 分支

**1. 当前判断**（无序列表）
- 本次巡检发现 2 个异常实例和 1 个失败实例，存在资源压力和连接泄漏风险。
- 172.30.34.73:8001：CPU 使用率达 92%，RSS 内存 1821MB，系统资源双高压力……
- 172.30.34.81:8001：文件描述符数达 980 并单调上升……
- 总体判定：异常实例需尽快执行排查或自愈预案，失败实例需优先恢复连通性。

**2. 总体建议**（三列表格）

| 异常实例 | 根因诊断结论 | 建议处置措施 |
| --- | --- | --- |
| 172.30.34.73:8001 | 系统资源双高压力，疑似内存泄漏与突增负载叠加。 | 1. Dump 堆内存分析；2. 重启或扩容释放压力。 |
| 172.30.34.81:8001 | 文件描述符单调递增，连接句柄泄漏。 | 1. 检查 TCP 连接释放逻辑；2. 定位未关闭句柄。 |
| 172.30.34.90:8001 | 巡检连接超时，可能宕机或网络拦截。 | 1. 检查端口与网络可达性；2. 核验防火墙规则；3. 确认进程存活。 |

### 4.3 failed 分支

**1. 当前判断**（无序列表）
- 本次巡检共覆盖 23 个对象，其中 3 个执行失败，失败占比 13%。
- 失败对象主要集中在连接超时、Agent 离线、权限不足三类原因。
- 失败对象无法采集 CPU、内存、RSS、线程数、FD 数等关键指标。
- 当前问题属于巡检执行失败，不等同于服务业务异常，需优先恢复采集能力。

**2. 总体建议**（两列表格 + 补充建议）

| 失败原因 | 建议动作 |
| --- | --- |
| 连接超时 | 确认目标对象网络连通性、端口访问状态、防火墙策略 |
| Agent 离线 | 确认 Agent 是否在线、是否正常运行、心跳是否恢复 |
| 权限不足 | 确认巡检脚本执行权限、指标访问权限、账号授权配置 |

补充建议：
- 建议优先处理严重级别较高的失败对象。
- 建议恢复采集能力后，重新执行失败对象巡检。
- 建议重新巡检后再生成健康判断或异常分析结论。

### 4.4 各分支数据形态对照

| 分支 | 当前判断 | 总体建议 |
| --- | --- | --- |
| normal | 无序列表 | 无序列表 |
| abnormal | 无序列表 | 三列表格（实例/根因/处置） |
| failed | 无序列表 | 两列表格（失败原因/建议动作）+ 补充建议列表 |

## 五、分析流程动画时序

AI 分析对话窗口按时间线逐步点亮各阶段：

```text
1.5s → 阶段 01 点亮（开始分析）
3.5s → 阶段 02 点亮（巡检对象分析）
6.5s → 阶段 03 点亮（最终结论，标记完成）
```

- 阶段节点用圆圈编号（1 / 2 / 3）+ 竖线连接
- 未点亮：灰色；已点亮：对应主题色 + 发光
- 阶段进行中显示"……中"的脉冲提示文案

## 六、重点对象交互规则（abnormal / failed）

### 1. 对象列表交互

- 阶段 02「全部巡检对象列表」默认前 5 条 + 「查看全部对象 (总数)」弹窗
- 阶段 02「对象详情」用 IP 按钮选择器切换当前对象

### 2. 当前选中对象联动

切换 IP 按钮后，「对象详情」区块整体刷新：
- 基础信息（含失败对象的失败原因行）
- 影响说明
- 异常指标表（仅异常对象）
- 异常原因分析（仅异常对象）

## 七、统一状态与视觉规则

### 1. 巡检结果状态

| 结果状态 | 含义 | 颜色 |
| --- | --- | --- |
| 正常 | 执行成功，未发现异常 | 绿色 |
| 异常 | 执行成功，但存在异常指标或对象 | 橙/红 |
| 失败 | 任务未成功执行，指标无法采集 | 红/灰 |

> "结果"字段只展示：正常 / 异常 / 失败；`info/warning/critical` 只作为"严重级别"。

### 2. 严重级别

| 严重级别 | 含义 | 颜色 |
| --- | --- | --- |
| 普通 (info) | 正常或低风险 | 灰蓝/绿 |
| 警告 (warning) | 存在风险需关注 | 橙色 |
| 严重 (critical) | 高风险需优先处理 | 红色 |

### 3. 标题层级规范

| 层级 | 用途 | 样式 |
| --- | --- | --- |
| 一级 | 阶段标题（01/02/03） | 16px / font-black / slate-100 |
| 二级 | 模块标题（1./2./3.） | 12px / font-bold / slate-200 + 竖条 |
| 三级 | 子模块（（1）（2）） | 11px / font-bold / slate-400 + 小圆点 |
| 四级 | 内容块（基础信息等） | 10px / font-bold / slate-500（中性灰）+ 微圆点 |

### 4. AI 能力边界

AI 只做辅助分析和轻量建议，**禁止**：自动重启 / 自动扩容 / 自动回滚 / 自动改配置 / 自动执行修复脚本 / 自动 Dump / 自动改代码。

## 八、导出报告

「查看报告」抽屉与导出的 MD / HTML 文档，结构与屏幕三阶段**完全镜像**：

```text
一、巡检基本状态概览   （计划信息 / 对象统计 / 巡检任务脚本）
二、巡检对象分析       （全部对象列表[全量] / 对象分析）
三、最终结论           （当前判断 / 总体建议）
```

> 导出的对象列表为**全量**（不截断）。详细字段与数据契约见《巡检报告MD规范.md》。
